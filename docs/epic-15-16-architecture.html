Per-message Workflow — ChatService.SendAsync

  Step 1 ── Assemble system message
    context = IAgentContextService.GetCurrent()
    systemMessage = providers
                      .Where(p ⇒ p.IsApplicable(context))
                      .Select(p ⇒ p.GetSection(context))
                      .Join("\n\n")

  Step 2 ── Model call
    response = OrchestratorPipeline.SendAsync(ModelCall,
                 { history: [...turns], systemMessage: "..." })
    → AzureChatClientProvider → Azure AI Foundry (Kimi-K2.5)

  Step 3 ── Parse and clean response
    (displayText, commands) = ChatCommandParser.Parse(rawText)
    displayText  — command markers stripped, shown to user
    commands[]   — typed objects, dispatched below

  Step 4 ── Detect STATE_TRANSITION  (internal — never returned)
    if commands contains StateTransitionCommand(mode):
      IAgentContextService.UpdateConversationState(mode)
      → AgentContext.ConversationState = ConversationState.FromMode(mode)
      → ExecutionStateProvider will reflect this on the NEXT Step 1
    filter StateTransitionCommand out of result

  Step 5 ── Return to ViewModel
    return ChatServiceResult(displayText, visibleCommands)

Command Dispatch — ChatViewModel.HandleCommandAsync

  Interactive commands — shown as UI panels, user decides what happens next:

    [FOLDER_SELECT:{reason}]          → OS folder dialog
                                          path → injected back to ChatService.SendAsync

    [PROJECT_CONFIRM:{name,intent}]   → confirm panel shown
                                          user clicks OK:
                                            ProjectService.CreateProjectAsync()
                                            ScaffoldService.CreateScaffoldAsync()
                                            IAgentContextService.SetProject(project, paths)
                                            → next Step 1: ActiveProjectProvider now applicable

    [PATH_PERMISSION_REQUEST:{path}]  → permission panel shown
                                          user approves:
                                            FileSessionGate.GrantReadAccess(path)


  Tool commands — executed silently, result injected back into conversation:

    [READ_FILE:{path}]   ─┐
    [WRITE_FILE:{path}]  ─┤──► FileSessionGate.CanRead / CanWrite(path)?
    [LIST_DIR:{path}]    ─┘      No  → emit PathPermissionRequestCommand (interactive above)
                                 Yes →
                                        OrchestratorPipeline → FileRead/Write/DirList provider
                                        result → ChatService.SendAsync (injected as tool result)


  STATE_TRANSITION — model signals conversation mode change (internal loop):

    [STATE_TRANSITION:{mode}]   filtered in Step 4 — ChatViewModel never sees it
    AgentContext.ConversationState updated → providers reflect new mode on next Step 1
